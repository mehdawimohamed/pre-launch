# Security Policy

## Reporting Security Issues

We take the security of this project seriously. Because this is a **public open-source repository**, please do **NOT** report security vulnerabilities through public GitHub issues, discussions, or pull requests.

### Preferred Method: GitHub Private Vulnerability Reporting

Please submit vulnerability reports directly and privately through GitHub:

1. Navigate to the **Security** tab of this repository on GitHub.
2. Select **Advisories** (under "Reporting").
3. Click **Report a vulnerability** to open a private advisory draft.
4. Include detailed information to help us understand and reproduce the issue:
   - Type of vulnerability (e.g., authorization bypass, SQL injection, secret leakage, XSS).
   - Step-by-step reproduction instructions or proof-of-concept.
   - Any proposed remediation if available.

### What to Expect

- **Acknowledgment:** We aim to acknowledge receipt of private vulnerability reports within 48 hours.
- **Assessment:** We will validate the reported issue and determine severity and impact.
- **Resolution:** A fix will be developed privately and deployed, followed by public disclosure coordinated with the reporter.

Thank you for helping keep this project and its users secure.
